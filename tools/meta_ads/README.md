# tools/meta_ads — งาน meta-ads-export

`export.py` ดึง Meta Ads ทุกระดับผ่าน Composio (บัญชี metaads เดิม · secret `COMPOSIO_API_KEY` เดิม) แล้วเขียนลงชีต **ข้อมูล Meta Ads ม.ค.-ต.ค. 2026 (ครบทุกระดับ)** (หาชีตและบัญชีโฆษณาด้วย hash ไม่เขียน ID ไว้ใน repo)

## รันเมื่อไร

| ทาง | ช่วงข้อมูล |
|---|---|
| อัตโนมัติทุกคืน 01:47 น. เวลาไทย (`cron 47 18 * * *` UTC) | 1 ม.ค. ของปี → **เมื่อวานตามวันของบัญชี (LA)** |
| push ไฟล์ใน `tools/meta_ads/**` หรือ workflow นี้ (ใส่ `[skip ci]` ใน commit ถ้าไม่อยากให้รัน) | เหมือนรอบอัตโนมัติ |
| กด Run workflow เอง: `since` / `until` / `only` (เว้นว่าง = ค่าเริ่ม) | ตามที่ใส่ |

- รอบละ ~26 นาที (ม.ค.–ต.ค.) และยาวขึ้นตามจำนวนเดือน · ~2,000 คำขอ Composio ต่อรอบ (Meta ~1,850 + Sheets ~150)
- ต้องเสร็จก่อน refresh-dashboard (06:20 น.) → obsidian-vault ที่อ่านแท็บ `โฆษณารายวัน` `ข้อความต้อนรับแชทของโฆษณา` `โฆษณารายเดือน` ไปจับคู่แชทกับโฆษณา · GitHub อาจเลื่อนรอบตั้งเวลา 1–3 ชม. จึงตั้งไว้ตี 1 กว่า
- concurrency group `meta-ads-export` → ไม่รันซ้อนกันเอง · repo public ไม่กินโควตานาทีฟรี

## สิ่งที่ทำทุกรอบ

1. ดึงใหม่ทั้งช่วง แล้ว **ลบและสร้างใหม่** 10 แท็บของงานนี้ (รวม `ตรวจข้อความต้อนรับซ้ำ`): ชุดโฆษณารายเดือน · โฆษณารายเดือน · โฆษณารายวัน · ข้อความต้อนรับแชทของโฆษณา · ผลลัพธ์ทุกประเภทรายเดือน · อายุและเพศ / ประเทศและจังหวัด / แพลตฟอร์มและอุปกรณ์ / รายชั่วโมง แยกแคมเปญ
2. ตรวจยอดใช้จ่ายและเริ่มแชทของทุกแท็บเทียบระดับบัญชี → log บอกแค่ "ตรง/ไม่ตรง" ตัวเลขจริงลงแท็บ `แหล่งข้อมูล`
3. แถว `สถานะงาน meta-ads-export` ในแท็บ `แหล่งข้อมูล` = ความคืบหน้า / "เสร็จแล้ว · ข้อมูลถึง <วัน LA>" / "ล้มเหลว: …"
4. แท็บ `อ่านก่อน`: เขียนบรรทัด "ช่วงข้อมูล" และ "ดึงเมื่อ" ใหม่ทุกรอบ
5. แท็บ `ตรวจข้อความต้อนรับซ้ำ` (เพิ่ม 30 ต.ค. 2026): โฆษณาที่เริ่มแสดงหรือสร้างใน 14 วันล่าสุด × ผลตรวจ ซ้ำ / ไม่ซ้ำ / ไม่มีข้อความต้อนรับ (เทียบกับทุกโฆษณาในชีต) ตามกติกา "ทุกโฆษณาใหม่ใช้ข้อความต้อนรับไม่ซ้ำ" · Weekly Pulse อ่านแท็บนี้ไปเตือนทีมยิงแอด · log พิมพ์แค่จำนวน · ถ้าส่วนนี้พังจะข้ามแท็บนี้ แท็บอื่นยังเขียนตามปกติ

แท็บรอบแรก (บัญชีโฆษณา · รายวัน · แคมเปญ · แคมเปญรายเดือน · ชุดโฆษณา · โฆษณาและครีเอทีฟ · ผลลัพธ์ทุกประเภท · breakdown ทั้งบัญชี · กลุ่มเป้าหมายที่บันทึก · ประวัติการแก้ไข · รูปภาพในบัญชี) **สคริปต์นี้ไม่เติม** — หยุดที่ 21 ต.ค. 2026 · obsidian-vault คิดยอดของบัญชี/แคมเปญ/โฆษณาจาก `โฆษณารายเดือน` แทน และเติมโฆษณาใหม่จาก `ข้อความต้อนรับแชทของโฆษณา` (ดู `tools/vault/README.md`)

## ข้อห้าม (repo public)

## ขึ้นปีใหม่ (ยังไม่ทำ — ทำก่อนหรือช่วง 1–5 ม.ค. 2027)

ตอนนี้ `SINCE` ค่าเริ่ม = `2026-01-01` และชื่อชีตมี "ม.ค.-ต.ค. 2026" · ตั้งแต่ ~2 ม.ค. 2027 วันจบจะข้ามปี สคริปต์จึง **หยุดไว้ที่ 31 ธ.ค. 2026** และขึ้น ⚠️ ในแถวสถานะ (ชีต 2026 ไม่เสีย แต่ไม่มีข้อมูลปีใหม่)

1. รอบสุดท้ายของปี 2026: ให้รอบอัตโนมัติวันที่ 2 ม.ค. ดึงถึง 31 ธ.ค. ครบก่อน (หรือกด Run เอง until=2026-12-31) แล้วเปลี่ยนชื่อไฟล์ชีตเป็น "ข้อมูล Meta Ads 2026 (ครบทุกระดับ)" (สคริปต์หาด้วย hash ของ ID ชื่อเปลี่ยนได้)
2. ปี 2027 เลือกทางใดทางหนึ่ง:
   - **ชีตใหม่ต่อปี (แนะนำ)**: สร้างชีต "ข้อมูล Meta Ads 2027 (ครบทุกระดับ)" (ทำสำเนาแท็บ `อ่านก่อน` + `แหล่งข้อมูล`) → แก้ `SHEET_HASH` เป็น hash ของ ID ใหม่ และ `SINCE` ค่าเริ่มเป็น `<ปีของเมื่อวาน LA>-01-01` · obsidian-vault เลือกชีต "ข้อมูล Meta Ads" ที่แก้ไขล่าสุด → ต้องแก้ให้อ่านทั้งสองชีต (ยอดปีก่อนจากชีต 2026 · ปีนี้จากชีต 2027) ไม่งั้นโน้ต Ads/ และ Monthly/ ของปี 2026 จะหาย
   - **ชีตเดียวยาวต่อเนื่อง**: ลบการหยุดที่ 31 ธ.ค. (`YEAR_END`) · รอบละนานขึ้น ~2.5 นาทีต่อเดือนข้อมูล และแท็บ `โฆษณารายวัน` เพิ่ม ~27,000 แถว/ปี (ชีตจำกัด 10 ล้านเซลล์ต่อไฟล์) → ไม่แนะนำเกิน 2 ปี
3. อัปเดตเอกสาร: skill `biopalm-data-map` (ตารางแหล่งข้อมูล + `references/meta-ads.md`) · prompt ของงานตั้งเวลา Weekly Pulse / Monthly Review ที่อ้างชื่อชีต
